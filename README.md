# Agentic Retrieval Projects: ProMSA-Lite and Agentic Document QA

This repository holds two related projects that share one codebase, one virtual environment and one LLM-client file. Both use an existing LLM as a *prompted agent* that decides, step by step, whether to search again or to answer.

| Part | Project | What it does |
|---|---|---|
| A | **ProMSA-Lite** | A prompted, laptop-scale version of *ProMSA (Progressive Multimodal Search Agents for Knowledge-Based VQA, ECCV 2026)*. Given a photo of a landmark and a question, the agent decides whether to search images, search text, or answer, over a small local knowledge base. |
| B | **Agentic Document QA** | Question answering over several PDFs, with hybrid search, source citations (file and page), "not found" detection, follow-up questions, a search-again loop and an evaluation dashboard. |
| C | **Earlier document tools** | Standalone scripts that summarise or answer questions about PDFs, web pages, images, videos, CSV/Excel files and YouTube videos, plus a single-document agent (`documents_agent.py`). |

Instead of training a custom RL policy, Part A uses a prompted LLM (Claude, GPT-4o, Gemini and others are supported). ProMSA is cited as the inspiration, not something that was reproduced.

# Part A: ProMSA-Lite

A prompted agent for knowledge-based visual question answering. Given a photo of a landmark and a question, it decides step by step whether to search images, search text, or answer.

### How the agent works

- **Agent loop** (`agent/agent_loop.py`): `ProMSALiteAgent(llm_client, search_tools, max_steps=5)` and `run(image_path, question)`. At every step the model sees the query photo and the conversation so far, and must reply with a `<thinking>` block plus exactly one of a `<tool_call>` (JSON) or an `<answer>`. This mirrors ProMSA's format, but the policy is a prompted LLM instead of an RL-trained model.
- **Tools** (`tools/search_tools.py`, class `SearchTools(top_k=3)`):
  - `image_search`: embeds the query photo with CLIP ViT-B/32 (OpenAI weights, via `open_clip`) and searches the image index. Used when the landmark is not recognised.
  - `text_search(query)`: embeds the query with `all-MiniLM-L6-v2` and searches the fact index. Used when the landmark is known but a specific fact is needed.
  - Both return up to 3 results (title, extract, score) and remember which titles were already shown for the current question, so a repeated search returns **new** results. This is the de-duplication idea from the ProMSA paper. `reset()` clears it, and the agent calls it at the start of every run.
- **Result summaries.** Each tool result is condensed by one extra LLM call (2 to 3 sentences relevant to the question) before it is added to the conversation, which keeps trajectories short.
- **Safeguards.** Invalid JSON in a tool call makes the agent retry. A reply with no valid tags is used as the answer. If the step budget runs out, the agent is asked for a final answer.
- **Output.** `run()` returns `answer`, `steps_used`, a `trajectory` log of every step, and `stopped` (`answer`, `format_error` or `budget`).

Run the steps in this order.

### 1. Scrape the knowledge base (no API key needed, needs internet)

```powershell
python data/scrape_wikipedia.py
```

The script reads the landmark names from `data/landmark_list.py` (60 landmarks in the starter list, nearly all very famous). For each landmark it calls Wikipedia's public summary API and saves:

- `data/knowledge_base.json`: one entry per landmark with `title`, `extract` (Wikipedia's short summary text), `image_path` and `url`.
- `data/images/<Title>.jpg`: the thumbnail Wikipedia returns for the page. Characters other than letters, digits, `_` and `-` in the title become underscores (for example `Eiffel_Tower.jpg`).

It waits 1.5 seconds between landmarks and retries when Wikipedia answers HTTP 429 (too many requests). Landmarks without a summary are skipped, and landmarks without a thumbnail stay in the knowledge base for text search but are left out of the image index. At the end it prints how many entries have images. To change the domain, edit `data/landmark_list.py` and re-run steps 1 and 2.

The knowledge base holds only these short summaries, not full Wikipedia articles, so many specific facts (for example the total length of a structure) may not be in it. The Great Wall entry, for instance, does not state the wall's length.

Check the result for disambiguation pages. If a title lands on one, the saved text is just something like "may refer to:" and there is no thumbnail. In the current knowledge base this happened for **Christ the Redeemer** and **Blue Mosque**, so neither has usable text or an indexed image. Use the exact Wikipedia page title for such landmarks in `data/landmark_list.py` (for example the specific page for the statue or for the Istanbul mosque), check the result, and re-run steps 1 and 2.

### 2. Build the search indices

```powershell
python data/build_text_index.py
python data/build_image_index.py
```

- `build_text_index.py` embeds "title. extract" for every entry with `all-MiniLM-L6-v2` and stores the vectors in a FAISS inner-product index (cosine similarity on normalised vectors): `data/text_index.faiss` and `data/text_index_meta.json`.
- `build_image_index.py` embeds every downloaded thumbnail with CLIP ViT-B/32 (OpenAI weights; GPU if available, otherwise CPU) and stores them the same way: `data/image_index.faiss` and `data/image_index_meta.json`. If no image can be embedded it stops with an error that points you to the scraper output.

Both scripts download their models on first use.

### 3. Choose and configure an LLM

The agent looks at the query photo on every step, so the model must accept **image input**. Open `agent/llm_client.py`, go to the bottom, and leave exactly one `DEFAULT_CLIENT` line uncommented, for example:

```python
DEFAULT_CLIENT = GeminiClient(model="gemini-3.8-flash")
# DEFAULT_CLIENT = ClaudeClient()
# DEFAULT_CLIENT = OpenAIClient(model="gpt-4o-mini")
```

Pass the model name explicitly, because the class defaults may be outdated. Then provide the matching API key (terminal variable or `.env` file, see Setup). Confirm which client is active with:

```powershell
python -c "from agent.llm_client import DEFAULT_CLIENT; print(type(DEFAULT_CLIENT).__name__, DEFAULT_CLIENT.model)"
```

Whether a given model accepts images depends on the provider and may change, so check its documentation if image questions fail.

### 4. Try a single question

```python
from agent.agent_loop import ProMSALiteAgent
from agent.llm_client import DEFAULT_CLIENT
from tools.search_tools import SearchTools

tools = SearchTools()
agent = ProMSALiteAgent(DEFAULT_CLIENT, tools, max_steps=5)

result = agent.run("data/images/Eiffel_Tower.jpg", "Who designed this structure?")
print(result["answer"])
print(result["steps_used"], "steps used")
```

### 5. Build a real test set

`eval/test_questions.json` is a list of entries like this (the image path is relative to the project root):

```json
{
  "image_path": "data/images/Eiffel_Tower.jpg",
  "question": "Who designed this structure?",
  "expected_answer": "Gustave Eiffel"
}
```

The test set in this repository has 10 questions about famous landmarks. Expand it to 30 to 100 questions for a real evaluation, and keep in mind:

- **Nine of the 10 current query images are the scraped thumbnails themselves.** The test set points to `data/images/<Title>.jpg`, the same files that `build_image_index.py` embedded, so `image_search` can return the identical image as its top match. This makes retrieval much easier than it would be on new photos. The tenth, Christ the Redeemer, has no usable knowledge-base entry (see step 1), so its answer can only come from the model's own knowledge. For a real evaluation use a different photo of each landmark (another angle, season or crop), for example a second image from Wikimedia Commons.
- **Include questions whose answer is only in the knowledge base** (less famous landmarks, specific facts). If the questions are about very famous landmarks, the model already knows the answer and retrieval has little room to help (see the results below).
- **Write `expected_answer` as the short core answer** (for example "marble" rather than "White marble"). The LLM judge is strict about wording.

#### A harder question set

`eval/test_questions_v2.json` has 20 questions about 20 landmarks, built to avoid the problems above. Each answer is a fact stated within the first 400 characters of that landmark's knowledge-base text, which is all the agent and `single_step_rag` can see, and every `expected_answer` is short. Each entry also has two extra fields, `landmark` and `support` (the words in the knowledge base that contain the answer). `evaluate.py` ignores them, and the checker below uses them.

1. **Add your own photos.** For each entry, download a *different* photo of the landmark (not the scraped thumbnail) and save it under `data/query_images/` with the file name used in the JSON, for example `Petra.jpg` or `Victoria_Falls.jpg`.
2. **Check the set before spending any API calls:**

```powershell
python eval/check_questions.py
```

It reports, per question, whether the image exists, whether it differs from the indexed thumbnail, and whether the `support` phrase really appears in the first 400 characters of the landmark's text. It stops nothing, so fix every line marked `FAIL`.

3. **Run it with separate result files**, so the 10-question results stay untouched. This needs two small changes at the top of `eval/evaluate.py`, which read the file names from environment variables:

```python
TEST_SET_PATH = os.path.join(HERE, os.environ.get("QUESTIONS_FILE", "test_questions.json"))
RESULTS_PATH = os.path.join(HERE, os.environ.get("RESULTS_FILE", "results.json"))
```

```powershell
$env:QUESTIONS_FILE="test_questions_v2.json"
$env:RESULTS_FILE="results_v2.json"
python eval/evaluate.py
```

Use one model for the whole run, because `results.json` does not record which model produced the answers. At roughly 8 LLM calls per question, 20 questions need about 160 calls.

### 6. Run the full evaluation

```powershell
python eval/evaluate.py
```

For every question it runs three methods (the two baselines are in `eval/baselines.py`):

- `direct_answer`: the model sees the photo and the question only, with no search.
- `single_step_rag`: one `image_search` is run, the top 3 results (title plus the first 400 characters of each fact text) are added to the prompt, and the model answers. It never uses `text_search`. This is the fixed retrieve-then-generate pipeline that the ProMSA paper argues against.
- the full agent (`ProMSALiteAgent`).

Each answer is judged YES or NO against `expected_answer` by the same LLM, prompted as a "strict but fair grader", and an accuracy summary is printed. Full results and the agent's trajectories are saved to `eval/results.json`.

- **Cost.** Each question takes roughly 8 LLM calls (the three methods, the agent's extra steps and result summaries, and three judge calls), so on a free tier a full run can take several days of quota.
- **Resuming.** Results are saved after every method. If a quota error stops the run, run the same command again: questions that already finished all three methods are skipped. To start over, delete `eval/results.json`. Questions are matched by their text, so keep each question's wording unique.
- **Stopping cleanly.** The script stops with a "[STOPPED]" message on a `RuntimeError` from the client, which the Gemini and Groq clients raise after exhausting their retries.

### Part A results

Results saved in `eval/results.json` (10 questions, single run, accuracy as judged by the LLM):

| Method | Correct | Accuracy |
|---|---|---|
| Direct answer (no retrieval) | 9 / 10 | 90% |
| Single-step RAG | 9 / 10 | 90% |
| ProMSA-Lite agent | 9 / 10 | 90% (1.9 steps on average) |

How to read these:

- **The one miss is a grading issue, not a system error.** On the Taj Mahal question the expected answer was "White marble". All three methods answered "marble", and the strict LLM judge marked each one wrong. By manual review all three answers are correct, which would make every method 10 / 10. Report both numbers and say which one is the manual correction.
- **The test is too easy to separate the methods.** The questions are about very famous landmarks that the model recognises and already knows. Nine of the ten query images are the indexed thumbnails themselves (see step 5), so image search is not tested on new photos, and `single_step_rag` effectively receives the correct landmark's text as context. The tenth (Christ the Redeemer) has no knowledge-base entry at all, so that answer came from the model's own knowledge in every method.
- **The agent did not clearly use retrieval to answer.** The knowledge-base entry for the Great Wall does not state its length at all, so no retrieval method could have supplied it. The agent's own summaries say the retrieved excerpts did not state the length, and it answered from general knowledge after 4 steps. More generally, the knowledge base holds one short Wikipedia summary per landmark, and only the first 400 characters of it are shown to the model.
- **With 10 questions**, each question is worth 10 points, so these results cannot separate the methods. A larger set that includes knowledge-base-only questions and new photos is needed for a meaningful comparison.
- `results.json` does not record which model produced the answers, so note the model next to these results.

# Part B: Agentic Document QA

Question answering over one or more PDFs. It shows which file and page each answer came from, refuses when the documents do not contain the answer, understands follow-up questions, and can search again when the first search was not enough.

### Features

| # | Feature | What it does |
|---|---|---|
| 1 | Multi-document store | Many PDFs in one store. Each chunk keeps its file name and page number. |
| 2 | Hybrid search | Keyword search (BM25) plus meaning-based search (sentence embeddings), merged with weighted Reciprocal Rank Fusion. |
| 3 | Confidence signalling | HIGH, MEDIUM or LOW from the cosine scores. On LOW the system refuses and makes no LLM call. |
| 4 | Citations | Each answer ends with a numbered source list (file, page, snippet) of the sources actually used. |
| 5 | Conversational memory | Follow-ups such as "what are its limitations?" are rewritten into standalone questions. |
| 6 | Agentic retrieval | The model may reply `SEARCH: <keywords>` when the evidence is incomplete (up to 3 steps). |
| 7 | Evaluation dashboard | Retrieval, calibration and answer-quality results written to an HTML page. |

### Setup

1. Complete the shared setup above.
2. Copy your PDFs into `data/pdfs/`. Make sure `pdfs` is a real folder, not a file.
3. Set `$env:GEMINI_API_KEY="YOUR_KEY"`.
4. The model name is the default in `rag/gemini_llm.py`:

```python
def make_gemini_llm(model: str = "gemini-3.8-flash", ...):
```

If the model is retired or unavailable to your account, list the models your key can use and put one of them in that line.

### Run the chat

```powershell
python chat.py
```

It loads every PDF in `data/pdfs/` and shows a `You>` prompt. Answers can take from a few seconds to a minute or two, because the client limits itself to 4 requests per minute and retries when the service is busy. Each answer shows `[understood as: ...]` when a follow-up was rewritten, `[step n: ...]` lines when the agent searched, a confidence line, the answer and a `Sources:` list.

Commands start with a slash. Without the slash the text is treated as a question.

| Command | What it does |
|---|---|
| `/docs` | List the loaded documents |
| `/add <path.pdf>` | Load another PDF |
| `/only <text>` | Answer only from documents whose file name contains `<text>`. `/only` alone clears it. |
| `/agent` | Agentic mode (default) |
| `/single` | Single-pass mode: one search, one answer |
| `/reset` | Forget the conversation |
| `/help`, `/quit` | Show commands, exit |

Example session:

```
You> how does the CYK algorithm parse a sentence?
You> what are its limitations?              (rewritten using the previous question)
You> what is the capital of France?         (refused, LOW confidence, 0 LLM calls)
You> /only NLP Unit
You> what are the stages of NLP?            (answers only from that PDF)
You> /only
You> how does syntactic analysis in NLP relate to CYK and Earley parsing?   (uses both PDFs)
```

### Web interface (Streamlit)

```powershell
pip install streamlit
streamlit run app.py
```

Streamlit prints a local address (normally `http://localhost:8501`) and opens it in the browser. Run the command from the `RAG_QA` folder.

- **Documents (sidebar).** Upload one or more PDFs, or load everything in `data/pdfs/` (this also happens automatically at start). Each loaded file is listed with its number of passages. The "Restrict answers to" box limits answers to the documents you choose.
- **Gemini (sidebar).** If `GEMINI_API_KEY` is set in the terminal before you start, it connects automatically. Otherwise paste a key and press "Connect Gemini". The key is kept only for the current session and is not saved to disk. Nothing is sent to Google until you ask a question.
- **Answer mode.** *Agentic* can search again, *Single pass* searches once, and **Retrieval only** shows the closest passages and the confidence level without calling any LLM. Retrieval only needs no API key, so it still works when the free quota is used up.
- **Answers.** Each answer shows a confidence label (green, orange or red) with the top similarity score, the number of LLM calls, the cited sources (file, page, snippet), and, for the agent, an expandable list of its search steps. Follow-up questions are rewritten using the conversation, and the rewritten question is shown as "Understood as". "Clear conversation" resets the memory.
- **Example questions** in the sidebar run a question with one click. Edit the `EXAMPLES` list at the top of `app.py` to match your own documents.
- If a model call fails (for example because the quota is used up), the message appears in the chat instead of stopping the app, and you can switch to Retrieval only.

### Web interface (React)

A second interface with the same features, built with React. A small FastAPI server (`server.py`) exposes the existing `rag/` code as a JSON API and serves the page in `web/`.

```powershell
pip install fastapi uvicorn python-multipart
python server.py
```

Then open `http://localhost:8000`. The server loads the embedding model and the PDFs in `data/pdfs/` at start, and connects to Gemini automatically if `GEMINI_API_KEY` is set. It listens on `127.0.0.1` only, so it is reachable from your own computer only.

- **No Node.js is needed to run it.** `web/app.js` is the compiled React code, with React included. Nothing is loaded from the internet.
- **Features:** drag-and-drop or file upload of PDFs, a document filter (tick documents to restrict answers), three answer modes (Agentic, Single pass, Retrieval only), a Gemini connection panel, a confidence badge, numbered citation markers with a source list (file, page, snippet), the agent's search steps, follow-up questions shown as "Understood as", example questions, and a light or dark theme that follows the system setting.
- **Files:** `server.py` (API and static files), `web/index.html` (page and styles), `web/src/App.jsx` (React source), `web/app.js` (compiled output).
- **API endpoints:** `GET /api/status`, `POST /api/upload`, `POST /api/load-folder`, `POST /api/connect`, `POST /api/ask`, `POST /api/reset`.
- **Changing the interface.** Edit `web/src/App.jsx`, then rebuild with Node.js 18 or newer:

```powershell
cd web
npm install
npm run build
cd ..
```

This regenerates `web/app.js`. The server keeps a single shared conversation, so it is meant for one user on one computer. Run either this interface or the Streamlit one at a time, because each loads its own copy of the embedding model.

### How it works

1. **Ingestion.** Each PDF page is split into chunks of about 180 words with 40 words of overlap. Chunks never cross a page boundary, so citations are exact. Each chunk is embedded and added to a BM25 keyword index.
2. **Hybrid search.** The question is searched by embeddings and by BM25, and the two rankings are merged with weighted Reciprocal Rank Fusion (BM25 weight 0.25, chosen with `eval/tune_weights.py`). Common words are removed from the keyword index.
3. **Confidence.** The best cosine score among the retrieved chunks decides: HIGH at 0.45 or above, LOW below 0.35, MEDIUM in between (thresholds in `rag/confidence.py`). On LOW the system returns "I couldn't find anything in the uploaded documents that answers this." without calling the LLM. On MEDIUM it answers with a warning.
4. **Answering and citations.** Retrieved chunks are numbered in the prompt. The model must cite those numbers, and only cited sources are listed, renumbered from 1.
5. **Memory.** For a follow-up, the model first rewrites the question into a standalone one using the last 3 turns.
6. **Agentic loop.** The model either answers or replies `SEARCH: <2 to 6 keywords>`. New chunks are added to the evidence (up to 8 chunks). The loop stops when the model answers, a search finds nothing new, a query repeats, or 3 steps are reached.

### Evaluation

Free retrieval-only run (no API calls):

```powershell
python eval/rag_eval.py
start eval\rag_dashboard.html
```

Full run with answer quality (uses API requests):

```powershell
python eval/rag_eval.py --with-llm --provider gemini
```

Notes:

- Progress is saved after every question in `eval/rag_answer_checkpoint.json`. If the run stops (for example on a quota limit), run the same command again to resume.
- **Do not use `--fresh` unless you want to delete all saved answers and start over.**
- The dashboard shows "Based on X of 18 questions". Only quote answer-quality numbers when all questions are done.
- The checkpoint records the model name. If you change the model, the saved answers are ignored.
- Latency in the dashboard includes rate-limit waiting, so it is not a reliable speed comparison.

`eval/rag_questions.json` holds the labelled questions:

```json
{"q": "what are the stages of NLP?",
 "gold_pages": [5, 11],
 "keywords": ["lexical", "syntactic", "semantic"],
 "answerable": true}
```

`gold_pages` are the pages that contain the answer, `keywords` are facts the answer should mention, and `answerable: false` marks questions the documents cannot answer.

Metrics: **Hit@4** (a correct page in the top 4), **MRR** (average of 1 / rank of the first correct page), **calibration** (answerable questions not flagged LOW, unanswerable ones flagged LOW), **key-fact coverage** (share of required keywords in the answer, a rough proxy) and **citation precision** (share of cited pages that are in `gold_pages`).

### Part B results

Test set: 18 questions (14 answerable, 4 unanswerable) over two PDFs (NLP Unit-I notes and Parsing Algorithms notes). Answer-quality numbers come from a single run of `gemini-3.8-flash`.

| Measure | Result |
|---|---|
| Retrieval Hit@4 | 100% (dense and hybrid) |
| Retrieval MRR | 0.74 hybrid, 0.70 dense |
| Unanswerable questions refused | 4 of 4 |
| Answerable questions wrongly refused | 0 of 14 |
| Key-fact coverage | 94% single pass, 98% agentic |
| Citation precision | 71% single pass, 79% agentic |

How to read these:

- Single-pass and agentic answering gave identical results on 11 of the 14 answerable questions. The coverage gain came from one multi-part question, where the agent searched a second time and found the missing page.
- With 14 answerable questions and one run, the differences between methods are indicative only.
- The BM25 weight and the LOW threshold were tuned on the same questions used for evaluation, so the retrieval and calibration numbers are optimistic.
- Reference pages were chosen by hand and only partly checked against the PDFs, so citation precision may be underestimated.

### Part B limitations and future work

- No "without retrieval" baseline was run for Part B.
- Questions that need both PDFs were not part of the labelled evaluation.
- The test set is small, and all results come from one model and one run.
- Gold pages are page numbers only. Both PDFs have a page 5, 10 and so on, so a citation to the wrong file's page could count as correct. Storing `[file, page]` pairs would fix this.
- Only text PDFs are supported. Scanned PDFs without a text layer give no chunks.
- The interface is a command-line chat, not a web page.

# Part C: Earlier document tools

Small standalone scripts, run from the `RAG_QA` folder. Part B does not use any of them.

| Script | What it does | Needs |
|---|---|---|
| `summarize_pdf.py` | Extracts the text of a PDF with `pypdf` and summarises it. Uses only the first 30,000 characters of long documents. Text only: scanned PDFs with no text layer give no text, because there is no OCR. | The key for the active `DEFAULT_CLIENT` in `agent/llm_client.py` |
| `summarize_pdf_native.py` | Sends the whole PDF (text plus images, charts and diagrams) to Gemini (`gemini-3.7-flash`) and prints a summary. If Gemini fails, it falls back to Claude. | `GEMINI_API_KEY` (or `GOOGLE_API_KEY`); `ANTHROPIC_API_KEY` for the fallback |
| `summarize_pdf_chat.py` | Interactive session: load a source once, then ask for a summary or ask questions, with the conversation kept between turns. | Same keys as above; see the notes below |
| `summarize_youtube.py` | Fetches a YouTube video's transcript (captions) and summarises it, or answers a question about it. Uses the first 30,000 characters of long transcripts. Fails if the video has no captions. | The key for the active `DEFAULT_CLIENT`; `youtube-transcript-api` |

Usage:

```powershell
python summarize_pdf.py "path\to\document.pdf"
python summarize_pdf_native.py "path\to\document.pdf"

python summarize_pdf_chat.py "path\to\document.pdf"
python summarize_pdf_chat.py "path\to\data.csv"
python summarize_pdf_chat.py "path\to\photo.jpg"
python summarize_pdf_chat.py "path\to\clip.mp4"
python summarize_pdf_chat.py "https://example.com/some-article"

python summarize_youtube.py "https://www.youtube.com/watch?v=VIDEO_ID"
python summarize_youtube.py "VIDEO_ID" "What are the main points made in this video?"
```

Notes on `summarize_pdf_chat.py`:

- **Supported sources:** PDF, CSV, Excel (`.xlsx`, `.xls`), text and Markdown, common image formats, common video formats, or a URL to a web page, image or video. Web pages are rendered to PDF with a headless browser, so the page's images and layout are kept. This needs `playwright install chromium` once.
- **Video** works only through Gemini, because Claude's API does not accept video. If Gemini fails on a video, there is no fallback.
- **Provider order:** it tries `gemini-3.7-flash`, then `gemini-3.6-flash`, then Claude, and checks this on every turn. If Claude takes over in the middle of a session, it does not see the earlier conversation.
- **Summary shortcut:** any message that contains the text "summar" is replaced by the built-in summary prompt, so use a different wording if you want to ask something about summaries.
- **Text and data files** are cut at 400,000 characters.
- Type `exit` or `quit` to leave.

The model names in these scripts are written into the code (`gemini-3.7-flash`, `gemini-3.6-flash`, `claude-sonnet-5`). Models are retired and renamed often, so if a script reports "model not found" or a quota error, edit the name to one that your provider currently offers.

**`documents_agent.py`** is a single-document version of the agent loop. `DocumentSearchTools` splits a document's text into overlapping character chunks and searches them with TF-IDF and cosine similarity, skipping chunks already seen for the same question. `DocumentAgent` runs the same `<thinking>` plus `<tool_call>` or `<answer>` loop as ProMSA-Lite with one tool, `search_document`, summarises each search result, and stops after `max_steps` (default 5). It is a module to import, not a script to run, and none of the scripts above import it. It needs `scikit-learn` and a client from `agent/llm_client.py`.

Part B replaces this single-document approach with multi-document hybrid search, citations and confidence checks.

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| `... API key is not set` when importing `agent.llm_client` | `DEFAULT_CLIENT` is created at import. Set the key for the active client first, or make a different client the only active line. |
| The wrong provider is used (for example OpenAI "no credits remaining") | Python uses the **last** uncommented `DEFAULT_CLIENT` line in `agent/llm_client.py`. Leave only one active, save, then run the `python -c ...` check from Part A step 3. |
| `OpenRouter model '...' was not found` | Free model names are retired often. Pick a current one from the OpenRouter model list. |
| `429` or "quota exhausted" | The provider's free allowance is used up. Wait for the reset (daily limits reset on the provider's schedule) and run again. Part B evaluation progress is saved. |
| `Gemini model '...' not found` (404) | The model is retired or unavailable to your account. List the models your key can use and update `rag/gemini_llm.py` (Part B) or the `DEFAULT_CLIENT` line (Part A). |
| `503` or `504` messages while answering | The service is busy. The client retries automatically. |
| `ImportError: cannot import name 'DocumentQA' ... circular import` | `rag/chat.py` must contain only the `ChatSession` code. The program you run is the root `chat.py`. |
| `python server.py` fails with `No module named 'fastapi'` | Run `pip install fastapi uvicorn python-multipart` in the active virtual environment. |
| Uploading a PDF in the React page fails with a message about `python-multipart` | Run `pip install python-multipart`, then restart `server.py`. |
| The React page shows "Cannot reach the server" | `server.py` is not running or has stopped. Start it again and reload the page. If port 8000 is busy, change the port in the last line of `server.py`. |
| `streamlit: command not found` | Install it with `pip install streamlit` in the active virtual environment, or run `python -m streamlit run app.py`. |
| Streamlit prints warnings about `torch.classes` | A known harmless warning from the file watcher. Ignore it, or start with `streamlit run app.py --server.fileWatcherType none`. |
| A command like `only NLP` acts like a question | Commands need the leading slash: `/only NLP`. |
| `No PDFs found in data/pdfs` | Create `data/pdfs` as a folder (not a file) and put PDFs in it. |
| Image questions fail in Part A | The selected model may not accept images, or the key or limits are wrong. Try another vision-capable model. |
| `build_image_index.py` prints `[skip] ... No such file` for every image on macOS or Linux | `knowledge_base.json` stores image paths with Windows backslashes (`images\Name.jpg`) when it was scraped on Windows. Re-run `scrape_wikipedia.py` on the system where you build the index, or replace the backslashes with `/` in the file. |
| `check_questions.py` reports `FAIL` | Read the note on that line: a missing image, a query image identical to the indexed thumbnail, or a `support` phrase that is not in the first 400 characters of the landmark's text. |
| `ModuleNotFoundError: No module named 'google.genai'` | Install the correct package: `pip install google-genai` (not `google-generativeai`). |
| `summarize_pdf_chat.py` fails on a web page URL | Run `pip install playwright` and then `playwright install chromium` once. |
| `summarize_youtube.py` says no transcript | The video has no captions, or the uploader disabled them. Try another video. |
| The Claude fallback in `summarize_pdf_native.py` or `summarize_pdf_chat.py` says the model was not found | The Claude model name is written into the script (`claude-sonnet-5`). Replace it with a model name your Anthropic account currently offers. |
| `ModuleNotFoundError: No module named 'dotenv'` | `agent/llm_client.py` imports `dotenv` at the top. Run `pip install python-dotenv`. |
| The Gemini client prints `Retrying in 83288s` (or another very long wait) | The daily quota for that model is used up, and the server asked for a long wait. Press Ctrl+C. `evaluate.py` and `rag_eval.py` keep their saved progress, so run them again after the quota resets. Adding a check in `GeminiClient._generate_with_retry` that raises a `RuntimeError` when the delay exceeds a few minutes makes the scripts stop by themselves. |
| `OpenAI ... no credits remaining` when you did not expect OpenAI | The last uncommented `DEFAULT_CLIENT` line in `agent/llm_client.py` is `OpenAIClient`. Make the line for your provider the only active one. |
